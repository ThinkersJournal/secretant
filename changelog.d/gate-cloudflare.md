kind: HTTP client behind a cargo feature (off by default)
---
Cloudflare Worker delivery and its HTTP client (`minreq`, with the TLS stack under it) are now behind the cargo feature `cloudflare`, off by default: a consumer of the store pulls no HTTP or TLS crate (the default build is 42 packages in the normal dependency tree, none of `minreq`, `rustls`, `ring`, `aws-lc-*`, `webpki*`, `openssl`). `cargo install secretant --features cloudflare` (or `cargo build --features cloudflare`) adds `secretant::cf`, the `CloudflareWorker` types and the `secretant cloudflare` command; without the feature that command says so. CI: a new job (`Default build has no HTTP or TLS stack`) fails if the default tree contains any of those crates and checks the feature does bring them in (negative control); the build and test job now also tests and lints with all features. The Cloudflare tests require the feature. Not published.
