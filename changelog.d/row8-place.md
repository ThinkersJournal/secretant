kind: installer Place step for files and environment files
---
New module `secretant::place_step`, row 8b (second half), designed in `docs/INSTALLER-STEPS.md` 4.3: `probe_place`, `plan_place`, `apply_place`, `read_back_place`, a thin step over `deliver` in the same four calls as the Store and Secrets steps. A plan carries the probe it was made from, so `apply_place` refuses (and writes nothing) if a target or the store changed since; a placement that needs nothing is not written (a re-run touches no file); a failing placement leaves its target as it was and the others go on. Plans, reports and read-backs carry names, indexes, versions and classes only. Verified by `tests/place_step.rs` (placed value absent from every plan, report and read-back, with a control; no-op; new version updates only what changed; stale plan; one failure) and two mutations (skip the stale-plan check, write unchanged targets) that each failed a test. Placing to a Cloudflare Worker (behind the `cloudflare` feature) is not in this step yet. Not published.
